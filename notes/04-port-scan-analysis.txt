-------------------------------------------------------
1. OBJECTIVE
-------------------------------------------------------

The objective of this investigation was to capture and analyze TCP traffic generated by a
controlled SYN scan and identify patterns associated with basic network reconnaissance.

The scan was performed against the local Kali Linux system (127.0.0.1) in a controlled laboratory environment.

-------------------------------------------------------
2. LAB SETUP
-------------------------------------------------------

Source / Scanner: 127.0.0.1

Target: 127.0.0.1

Network Interface: lo (loopback)

Scanning Tool: Nmap

Scan Type: TCP SYN Scan (-sS)

Ports Tested: 8075-8085

A temporary HTTP service was intentionally started on TCP port 8080 using Python's built-in HTTP server.

Command used to create the test service:
python3 -m http.server 8080 --bind 127.0.0.1

Nmap command:
sudo nmap -sS -p 8075-8085 127.0.0.1

-----------------------------------------------------
3. OBSERVED TRAFFIC
-----------------------------------------------------

The Wireshark capture showed multiple TCP SYN packets sent to different destination ports on 127.0.0.1.

Examples observed in the capture:

Source Port: 61465
Destination Port: 8080
TCP Flag: SYN

Source Port: 61465
Destination Port: 8084
TCP Flag: SYN

Source Port: 61465
Destination Port: 8079
TCP Flag: SYN


-----------------------------------------------------
4. OPEN PORT ANALYSIS
-----------------------------------------------------

TCP port 8080 was identified as open.

The following packet sequence was observed:

1. 127.0.0.1:61465 -> 127.0.0.1:8080
   TCP SYN

2. 127.0.0.1:8080 -> 127.0.0.1:61465
   TCP SYN-ACK

3. 127.0.0.1:61465 -> 127.0.0.1:8080
   TCP RST

The SYN-ACK response indicates that a service was listening on TCP port 8080.

The RST packet occurred because the Nmap SYN scan does not complete the normal TCP three-way handshake.

------------------------------------------------------
5. CLOSED PORT ANALYSIS
------------------------------------------------------

TCP ports such as 8079 and 8084 returned TCP RST-ACK responses after receiving SYN packets.

Example:
127.0.0.1:61465 -> 127.0.0.1:8084
SYN

127.0.0.1:8084 -> 127.0.0.1:61465
RST, ACK

This behavior indicates that no service was accepting TCP connections on the tested closed port.

--------------------------------------------------
6. TRAFFIC PATTERN
--------------------------------------------------

The capture showed a single source repeatedly attempting connections to multiple TCP
destination ports on the same target within a short period.

This pattern is consistent with TCP port-scanning activity.

In a real environment, similar behavior could represent network reconnaissance and would require
investigation of the source host, destination asset, user activity, and surrounding network events.

------------------------------------------------------

------------------------------------------------------

Assessment:
The traffic pattern is consistent with a TCP SYN port scan.
Because this activity was intentionally generated as part of a controlled laboratory exercise,
it does not represent an actual malicious incident.

-----------------------------------------------------
8. POTENTIAL IMPACT
-----------------------------------------------------

In a real network, port scanning may allow an attacker to identify accessible
services and potential attack surfaces.

The scan itself does not demonstrate successful exploitation or compromise.

Further investigation would be required to determine whether the activity was
authorized reconnaissance, vulnerability assessment, or malicious scanning.

---------------------------------------------------
9. RECOMMENDED SOC RESPONSE
---------------------------------------------------

If similar activity were detected in a production environment:

1. Identify the source host and associated user/device.

2. Determine whether the scanning activity was authorized.

3. Review additional network logs for continued scanning or connections to discovered services.

4. Check whether the targeted system contains exposed or unnecessary services.

5. Investigate subsequent authentication attempts or exploitation activity.

6. If unauthorized, follow the organization's incident response process and consider appropriate containment.

11. CONCLUSION
----------------------------------------------------

The investigation successfully captured and analyzed a controlled TCP SYN scan using Wireshark.

Packet-level analysis demonstrated the difference between an open TCP port responding
with SYN-ACK and a closed TCP port responding with RST-ACK.

The repeated SYN requests to multiple destination ports produced a traffic pattern
consistent with network reconnaissance / port scanning.

This exercise demonstrated practical use of Wireshark for identifying source and destination
IP addresses, TCP ports, TCP flags, connection behavior, and suspicious network activity.
